# Contents

- `bin/` – the `ghostget-skills` CLI (list, run, verify, tools, doctor, install-skills).
- `src/` – the in-process runner, the bounded Ghostget CLI boundary, and the pure fn registry.
- `tools/` – reviewed tool implementations and the `cmd:` registry mirror; every tool is a read.
- `programs/` – ALGAL organism manifests; inner programs are embedded by pinned digest.
- `skills/` – the agent skills installed by `install-skills`; one per consumer-facing program plus the router.
- `fixtures/` – recorded Ghostget responses and the Hraness collection plan used by tests, smoke, and bench.
- `tests/`, `scripts/check.ts`, `bench/` – the gate and the measured comparison.
- `docs/` – the seam contract, programs, healing boundaries, and metrics methodology.

# Guidelines

- Use Bun 1.3.14. `bun run check` is the complete local gate and the CI gate; keep it green and deterministic (no provider, browser, network, or account access in tests, smoke, or bench).
- Pin `@hraness/ghostget` and `@hraness/algal` to immutable releases or full commits. Never point them at sibling paths.
- Every program declares `maxAgentCalls: 0`. Put record-shaping logic in `src/fns.ts` (pure, total, never throws on foreign input), effects in `tools/tool.ts` with a matching signature in `tools/ghostget.tools.json`, and routing in the manifest.
- The only Ghostget access is `src/ghostget-cli.ts`: fixed argv, `--json`, stdin input, byte caps, one deadline, TERM grace before KILL, `GHOSTGET_BIN` only as an absolute path. Tools never run mutations; `ghostget.invoke.read.v1` refuses any non-R1 receipt.
- Keep cookies, tokens, subjects, realm fingerprints, cache keys, raw provider responses, and local paths out of reports, receipts, fixtures, docs, and Git. The privacy gate scans for them.
- After editing an embedded program run `bun scripts/pin-digests.ts`; after touching `programs/`, `src/`, `tools/`, `fixtures/`, or `bench/` regenerate `bench/report` with `bun bench/run-bench.ts`.
- A receipt is execution evidence, not provider attestation. Do not describe recorded runs as live results.
- Deliver changes to `main` through a pull request with the `Check` workflow green.
- Follow `WRITING.md` for internal prose and `STYLE.md` for the README, docs, skills, and package description.
